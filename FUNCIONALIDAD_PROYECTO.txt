================================================================================
 1. ARQUITECTURA GENERAL Y FLUJO MVC
================================================================================
El proyecto sigue el patron MVC clasico de Spring Boot:

    Navegador ---> Controlador @Controller ---> Servicio @Service ---> Repositorio @Repository ---> MySQL
                                |
                                v
                         Plantilla Thymeleaf .html  (vista)

* Las URLs entran por los @GetMapping/@PostMapping de los controladores.
* Spring Security intercepta TODA peticion y aplica reglas de roles (ver 6.1).
* Si el rol del usuario logueado tiene permiso, el controlador llama al servicio.
* El servicio aplica reglas de negocio y valida datos, luego llama al repositorio.
* El repositorio (interfaz JpaRepository) genera SQL automaticamente y consulta MySQL.
* El controlador recibe la entidad, la pone en el Model y devuelve el nombre de
  la plantilla Thymeleaf que renderiza el HTML final.

Capas y paquetes:
  com.ludwingvasquez.kinalapp
    .config       -> SecurityConfig, AdminSeeder, InitialSetupService
    .controller   -> 9 controladores HTTP
    .service      -> Interfaces I* + sus implementaciones *Service
    .repository   -> Interfaces JpaRepository (Usuario, Cliente, Producto, Venta, Detalle)
    .entity       -> Entidades JPA mapeadas a tablas MySQL + POJO Notificacion

================================================================================

  ADMIN    -> Acceso TOTAL. Puede gestionar usuarios, clientes, productos,

6.1 SecurityConfig.java
--------------------------------------------------------------------------------
@Configuration / @EnableWebSecurity
   -> registra esta clase como configuracion de Spring Security.

constructor con CustomUserDetailsService
   -> inyecta el servicio que carga usuarios desde MySQL.

@Bean SecurityFilterChain securityFilterChain(HttpSecurity http)
   -> construye la cadena de filtros HTTP. REGLAS DE AUTORIZACION:

   .requestMatchers("/css/**","/js/**","/img/**","/webjars/**").permitAll()
      Recursos estaticos: cualquiera puede descargarlos.

   .requestMatchers("/","/login","/registro","/setup","/error","/acceso-denegado")
      .permitAll()
      Paginas publicas (no requieren login).

   .requestMatchers("/dashboard").hasAnyRole("ADMIN","USER","CLIENTE")
      Cualquier usuario logueado entra al dashboard.

   .requestMatchers("/usuarios/**").hasRole("ADMIN")
      Modulo de Usuarios: SOLO admin.

   .requestMatchers("/productos/nuevo","/productos/editar/**",
                    "/productos/eliminar/**","/productos/actualizar/**",
                    "/productos/exportar/**").hasAnyRole("ADMIN","USER")
      Crear/editar/borrar/exportar productos: admin y empleados.

   .requestMatchers("/productos","/productos/","/productos/dashboard",
                    "/productos/{id:[0-9]+}").hasAnyRole("ADMIN","USER","CLIENTE")
      Listado y ficha de producto (lectura): tambien para CLIENTE.

   .requestMatchers("/clientes/**").hasAnyRole("ADMIN","USER")
      Modulo Clientes: NUNCA para CLIENTE.

   .requestMatchers("/ventas/nueva","/ventas/guardar","/ventas/mis-ventas/**")
      .hasAnyRole("ADMIN","USER","CLIENTE")
      El cliente puede CREAR su compra y ver sus propias ventas.

   .requestMatchers("/ventas/editar/**","/ventas/eliminar/**",
                    "/ventas/actualizar/**").hasRole("ADMIN")
      Editar/eliminar ventas: SOLO admin.

   .requestMatchers("/ventas/**").hasAnyRole("ADMIN","USER")
      Resto de operaciones de ventas: admin y empleados.

   .requestMatchers("/detalles_ventas/**").hasAnyRole("ADMIN","USER")
      Detalles de venta: admin y empleados.

   .anyRequest().authenticated()
      Cualquier otra ruta exige sesion iniciada.

   .formLogin(...) -> login form personalizado en /login con campos username
                       y password. Tras login redirige a /dashboard. Si falla,
                       /login?error=true.
   .logout(...)    -> logout en /logout (GET o POST), invalida sesion y borra
                       cookie JSESSIONID. Redirige a /login?logout=true.
   .sessionManagement(...maximumSessions(1)) -> solo una sesion activa por
                       usuario; si se loguea otra vez, la anterior expira
                       y se manda a /login?expired=true.
   .exceptionHandling(...accessDeniedPage("/acceso-denegado"))
                    -> si un usuario intenta entrar a una ruta sin rol,
                       Spring lo manda a la pagina amigable de "Acceso denegado".
   .authenticationProvider(authenticationProvider())
                    -> registra el DaoAuthenticationProvider que abajo se define.

@Bean PasswordEncoder passwordEncoder()
   -> devuelve un BCryptPasswordEncoder (hash seguro de contrasenas).

@Bean DaoAuthenticationProvider authenticationProvider()
   -> usa CustomUserDetailsService + BCrypt para validar credenciales.

@Bean AuthenticationManager authenticationManager(AuthenticationConfiguration)
   -> expone el AuthenticationManager por si se necesita autenticar manualmente.

6.2 AdminSeeder.java
--------------------------------------------------------------------------------
@Component       -> Spring lo detecta como bean.
implements CommandLineRunner -> Spring lo ejecuta automaticamente
                                 una vez al arrancar la app.

Constantes:
   ADMIN_USERNAME = "admin"
   ADMIN_PASSWORD = "admin12345"
   ADMIN_EMAIL    = "admin@kinalapp.com"
   ADMIN_ROL      = "ADMIN"

run(String... args):
   1. usuarioRepository.findByUsername("admin") busca el admin en BD.
   2. Si existe:
        - Si el rol no es ADMIN, lo corrige.
        - Si el estado es null o != 1, lo activa.
        - Si la contrasena guardada no coincide con admin12345
          (passwordEncoder.matches), la re-encripta con BCrypt y la actualiza.
        - Si hubo cambios, guarda.
   3. Si NO existe: crea un Usuario nuevo con esos datos, la contrasena
      hasheada con BCrypt y estado=1, y lo guarda.
   => Asi SIEMPRE se puede iniciar sesion como admin/admin12345.

6.3 InitialSetupService.java
--------------------------------------------------------------------------------
@Service @Transactional
Sirve a SetupController para flujo legado de "primer arranque". No se usa
en flujo normal porque ya tenemos AdminSeeder. Metodos:

  requiereConfiguracionInicial()
     Devuelve true si la tabla usuarios esta vacia.

  crearPrimerAdmin(username, password, email)
     - Lanza error si ya hay usuarios.
     - Valida campos (no vacios) y unicidad de username.
     - Crea Usuario con rol ADMIN, estado 1 y password con BCrypt.
     - Lo guarda usando usuarioService.guardar().

6.4 CustomUserDetailsService.java
--------------------------------------------------------------------------------
@Service que implementa UserDetailsService de Spring Security.

  loadUserByUsername(username):
     1. usuarioRepository.findByUsername(username).
     2. Si vacio -> UsernameNotFoundException ("Usuario no encontrado").
     3. Si estado != 1 -> UsernameNotFoundException ("Usuario inactivo").
     4. Toma el rol (default "USER") y construye una SimpleGrantedAuthority
        con prefijo "ROLE_" + rol.toUpperCase()  (Spring Security requiere
        ese prefijo cuando usamos hasRole(...)).
     5. Devuelve un objeto User de Spring con username, password (hash de BD),
        accountNonExpired/locked/credentialsNonExpired/enabled=true y la lista
        de authorities.


================================================================================
 7. ENTIDADES JPA
================================================================================

7.1 Usuario.java
--------------------------------------------------------------------------------
@Entity @Table(name="usuarios")     -> mapea tabla usuarios.
Campos:
  @Id @GeneratedValue IDENTITY       -> codigo_usuario BIGINT autoincremental.
  username, password, email, rol    -> VARCHAR.
  estado                             -> BIGINT (1=activo, 0=inactivo).
Constructor vacio y constructor completo + getters/setters tradicionales.
@JsonProperty("codigo_usuario")     -> al serializar a JSON, usa snake_case.

7.2 Cliente.java
--------------------------------------------------------------------------------
@Entity @Table(name="clientes")
  @Id String DPICliente (dpi_cliente) -> PK natural, no autogenerada.
  nombreCliente, apellidoCliente     -> nombre completo.
  direccion                          -> texto libre.
  estado (Integer)                   -> 1 activo / 0 inactivo.
  fotoUrl                            -> URL o ruta de foto opcional.

7.3 Producto.java
--------------------------------------------------------------------------------
@Entity @Table(name="productos")
  @Id @GeneratedValue codigo_producto (Integer)
  nombre_producto, precio (Double), stock (Integer), estado (Long).

7.4 Venta.java
--------------------------------------------------------------------------------
@Entity @Table(name="ventas")
  @Id @GeneratedValue codigoVenta (Long).
  fechaVenta (LocalDate)            con @JsonFormat para formato yyyy-MM-dd.
  estado (Long)                     1 = activa / 0 = anulada.
  cliente -> @ManyToOne LAZY  FK dpi_cliente (referencia Cliente.DPICliente).
  usuario -> @ManyToOne LAZY  FK codigo_usuario (Usuario que registro la venta).
  detalles -> @OneToMany mappedBy="venta" CASCADE.ALL LAZY
              + @JsonIgnoreProperties("venta") para evitar ciclos de serializacion.

7.5 DetalleVenta.java
--------------------------------------------------------------------------------
@Entity @Table(name="detalles_ventas")
  @Id @GeneratedValue codigoDetalle.
  venta (Venta)  @ManyToOne EAGER FK codigo_venta + @JsonIgnoreProperties("detalles").
  producto (Producto) @ManyToOne EAGER FK codigo_producto.
  cantidad (Integer), precioUnitario (Double), estado (Long).

7.6 Notificacion.java
--------------------------------------------------------------------------------
POJO simple (NO entidad JPA). Se usa en memoria para mostrar tarjetas de
notificacion en el dashboard (stock bajo, ultima venta, ingresos, etc.).
Campos: id, tipo, titulo, mensaje, fecha, leida, icono, color.

 9. INTERFACES Y SERVICIOS
================================================================================
Cada modulo tiene una interfaz I*Service y una clase *Service que la implementa.
Esto permite inyectar la interfaz en los controladores y desacoplar la logica.

9.1 IUsuarioService / UsuarioService
   listarTodos, buscarPorId, guardar, actualizar, eliminar, existePorCodigo,
   buscarPorUsername.
   validarUsuario:
     - username no vacio.
     - password >= 8 caracteres.
     - email con @ y .
     - estado no nulo.

9.2 IClienteService / ClienteService
   listarTodos, guardar, buscarPorDPI, actualizar, eliminar, existePorDPI,
   listarPorEstado.
   validarCliente:
     - DPI no vacio, nombre y apellido obligatorios.
   guardar: si estado==0 fuerza estado=1.

9.3 IProductoService / ProductoService
   listarTodos, guardar, buscarPorCodigo, actualizar, eliminar,
   existePorCodigo, listarPorEstado.
   validarProducto:
     - nombre obligatorio.
     - precio >= 0.
     - stock >= 0.

9.4 IVentaService / VentaService
   listarTodos, guardar, buscarCV (por codigo venta), actualizar, eliminar,
   existePorCV, listarActivas, contarVentasPorCliente,
   calcularTotalVentasPorCliente, contarTotalVentas, calcularIngresosTotales,
   listarVentasPorCliente.
   guardar:
     - verifica que el Cliente y el Usuario existan.
     - si no hay fecha, pone LocalDate.now().
     - estado=1 por defecto.
   calcularIngresosTotales: suma cantidad * precioUnitario de detalles activos.

9.5 IDetalleVentaService / DetalleVentaService
   listarTodos, guardar, buscarPorId, actualizar, eliminar, existePorId,
   listarPorVenta.
   guardar:
     - exige venta y producto validos.
     - cantidad > 0.
     - estado=1 por defecto.

10.1 LoginController
--------------------------------------------------------------------------------
ROLES_PERMITIDOS = {"USER","CLIENTE"}  (registro publico no permite ADMIN).

GET "/"              -> redirect:/login
GET "/login"
   - Si ya hay sesion, redirect:/dashboard.
   - Si ?error=true muestra "Usuario o contrasena incorrectos".
   - Si ?logout=true muestra "Has cerrado sesion".
   - Devuelve template "login".

   1. Valida que rol enviado este en {"USER","CLIENTE"}; si no, default "CLIENTE".
   2. Si el username ya existe -> error.
   3. password.length() >= 8.
   4. email debe contener @ y .
   5. Crea Usuario, encripta password con BCrypt, estado=1.
   6. Guarda con usuarioService.guardar() (valida tambien en service).
   7. Manda flash "toastExito" y redirect:/login.

10.2 SetupController
--------------------------------------------------------------------------------

Con AdminSeeder este flujo rara vez se usa, pero queda como fallback.

GET "/setup"  -> si ya hay usuarios, redirect a /login. Si no, muestra form.
POST "/setup" -> valida username (>=3), password (>=8) y email con @ y .,
                 luego initialSetupService.crearPrimerAdmin(...). Redirect /login.

10.3 HomeController
--------------------------------------------------------------------------------
GET "/dashboard" (Model, UserDetails, ?periodo)
   1. nombreUsuario = userDetails.getUsername() o "Usuario".
   2. rolUsuario   = primer authority sin "ROLE_".
   3. emailUsuario = usuarioService.buscarPorUsername(...).getEmail().
   4. Calcula:
        totalProductos, totalClientes, totalVentas, totalUsuarios.
        ingresosTotales = suma de cantidad*precioUnitario en todos los
                          DetalleVenta de todas las Venta.
        productosBajoStock = productos con stock < 10.
        clientesActivos    = listarPorEstado(1).size().
   5. Construye lista de Notificacion:
        - hasta 3 alertas de stock bajo.
        - notificacion de ultima venta (codigo + total).
        - notificacion de ingresos totales si > 0.
        - alerta si no hay clientes.
   6. usuariosRecientes = los primeros 5 que NO sean "admin".
   7. Agrega TODO al modelo y devuelve "dashboard".

GET "/inicio"        -> redirect:/dashboard.
GET "/logout-legacy" -> redirect:/logout.

obtenerIniciales(nombre):
   parte por . o espacio o @ y construye 2 letras (ej. "luis perez" -> "LP").

14. FLUJO COMPLETO DE EJECUCION
================================================================================
1. Abrir MySQL Workbench, ejecutar /database/init_kinalapp.sql para crear
   tablas y poblar productos+clientes (opcional: Hibernate lo crea solo, pero
   el script poblaria los productos).
2. mvn spring-boot:run  (o ejecutar KinalappApplication desde el IDE).
3. Spring Boot levanta Tomcat en http://localhost:8302.
4. AdminSeeder corre, crea o repara el admin (admin / admin12345).
5. Ir a http://localhost:8302/login.
6. Ejemplos:
   - Login con admin/admin12345  -> ve y gestiona TODO.
   - Registrar nueva cuenta como USER -> ve clientes, productos, ventas
     (sin acceso a /usuarios).
   - Registrar nueva cuenta como CLIENTE -> solo ve productos y puede
     comprar (/ventas/nueva).
7. Cerrar sesion: GET o POST /logout.
